---

I decided to try to write something up without using AI this time. AI set up the Jekyll pipeline and README.md, but I don't really want the AI to write the content of these blog posts for me, or if I include AI-written text, it should be very easy to distinguish what is AI-written and what is from me. It is a pretty convenient workflow with Jekyll: just run a Python script and add a single string as an input argument; that string is used as the title and filename for the blog post. Not entirely sure how long I want each post to be, but I guess it is sort of flexible. Some technical posts may get very long with a lot of diagrams or other visuals, while some others may be just way shorter but still interesting, hopefully.

Markdown is way easier to learn and handle than some other document scripts such as LaTeX. However, one still has to kinda learn the syntax to make **special text** or other <mark style="background-color: lightgray; color: black;">cool visuals</mark>. The simplicity of Markdown is really convenient and should help make it straightforward to make spontaneous posts without having to allocate too much brainpower to formatting, so one can instead just focus on the content. Even though I may not let the AI write the posts for me, I'm probably going to have it correct grammar mistakes or, in some cases, double-check factual statements, or use it adversarially to think some thoughts through to check if they can hold water or not before posting.
